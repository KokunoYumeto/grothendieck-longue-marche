# Second-pass diplomatic transcription

Scope: the 26 scans listed in `page_order.json`, in that order: 97/019; 123/002–003, 016–020, 022–023, 028, 040; 162-1/002–010; 162-6/002–006.

The page files and combined LaTeX fragment use the supplied Codex preamble. The changes log records differences against witnesses C and H, including textual state and placement, with image evidence. The collation TSV contains H differences only. The doubts file begins with the cumulative notation table. The inventory uses `cote/scan` in its scan column to avoid collisions between identically numbered scans in different cotes.

`readers/PAGE/R1`, `R2`, and `R3` preserve the fresh readers' independent complete readings, reports and analytical crops. `decisions/` preserves the main reader's consolidation records. `briefs/` preserves the common conventions and reader brief versions. Tight crops are work evidence; full supplied scans, witness files and the input archive are not duplicated here. Crop manifests give the source image name, pixel box, rotation and resize. The attached archive and this record together permit continuation from a checkpoint.

`CHECK_EVENTS.tsv` distinguishes proof/computation checks from statements carried as background. Reading a statement is not a proof check. No OCR, text-recognition, external edition or internet research is used.

Sources: supplied scans from the Université de Montpellier fonds Alexander Grothendieck. Witness C: supplied Codex sessions H97-01, C123-01, C123-02, H162-01 and H162-02. Witness H: Michel Hua's Commutator project, `Commutator-IO/grothendieck-project`, commit `aef7db2`; its own editorial descriptions and normalized macro conventions are not manuscript text. Witness S: supplied sweep of 18–19 November 2026; only applicable readings are decided against the images.

Run identity: GPT-6 Astra Pro, with three fresh independent agents for each page and a main reader. The runtime does not expose an effort setting, so none is invented in this record. No human verification is claimed.

Completion state, timestamps, checkpoint names and frozen transcription hashes are recorded in `progress.log`. A checkpoint is an unfinished work snapshot; the final archive contains the completed deliverables.

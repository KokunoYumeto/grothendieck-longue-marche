# Lossless crop transport

Checkpoint 04 exceeded the persistent upload service’s 512 MiB file limit. Its original ZIP was retained unchanged. A transport copy with the same basename stores the crop images as lossless JPEG XL files. This changes only storage encoding: there is no resizing, color conversion, denoising, or change to any pixel. Each decoded image is compared byte-for-byte with the original pixel array, and the exact original PNG is reconstructed and its SHA-256 checked before the replacement is accepted. Non-image entries are preserved byte-for-byte.

The ZIP includes CROP_COMPRESSION_MANIFEST.json, CROPS_README.md, and scripts/restore_crops.py. The restoration script recovers the original crop filenames and bytes, so references ending in .png in the reading records remain resolvable. Pillow and an FFmpeg build with JPEG XL support are required for restoration. JPEG XL viewers can also inspect the archived images directly. Original PNGs remain present during adjudication; only archive transport copies use this encoding. Subsequent checkpoints and the final ZIP use this verified transport where needed. All crops, including first and independent second readings and main-reader details, are included.

## Version 2 transport, from checkpoint 06

The version 2 archive uses CROP_COMPRESSION_MANIFEST_V2.json and CROPS_README_V2.md with the same scripts/restore_crops.py entry point. Canonical crops are stored losslessly as above. Some additional rotated or enlarged helper views are stored as exact, declarative derivations of an included parent crop, rather than as a second compressed payload. Every such recipe is accepted only after the complete regenerated PNG bytes match the original PNG SHA-256. These recipes reproduce the already-created helper files; they do not reduce resolution or discard a crop. All non-PNG original entries retain their exact bytes. No original source scan is needed for restoration.

The version 2 test on the immutable checkpoint 05 snapshot restored all 778 original PNGs and independently compared all 1,244 original entries, with no mismatches. The original checkpoint 05 and its earlier uploaded transport were not modified. The verification report and encoder/restore source are retained under qa/ and scripts/. The final archive must be extracted and its restore command run to recover referenced .png paths; --verify-all checks all original entries. Pillow, NumPy for the documented neutral-color helper recipes, and an FFmpeg build supporting JPEG XL are required. The README records the exact generation environment and commands.

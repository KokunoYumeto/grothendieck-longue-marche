# Carryover audit and postbuild command order

This runbook concerns evidence transfer. It does not approve the forthcoming publication PDFs. The audit used synthetic files only; it did not read publication PDFs or modify existing observations, findings, candidates or validations. Its reproducible result is `work/data/carryover_tool_audit.json`.

## Rules enforced by the tools

- A selected-page observation carries only when its PNG-file SHA256 and decoded RGB SHA256 both match. The RGB digest includes dimensions. A different physical page number is allowed only for one unique matching attributed historical row. Ambiguous or changed images stay pending. Review history retains the original page, PDF hash and complete observation.
- Native carry additionally requires exact per-finding source, repair and inspection identity. An added global inventory hash does not invalidate unchanged old identities. New IDs, missing historical observations, changed requirements, changed images and ambiguous matches stay pending. Every cited historical image must match; one matching crop is insufficient when another cited image changes.
- The original frozen inventory has36 findings. Its five primary queues have31/35/33/35/33 observations. The current definitions were compared against that frozen inventory during this audit and had no changes. The root curator must preserve those original definitions while adding the new ones; future queue counts are read dynamically.
- Selected rendering, supplied observation recording and master-review transfer use the same per-book lock. A long operation cannot overwrite a concurrent title-page observation. Use an immutable per-build inspection index when recording page-number-only notes; mismatched PDF, PNG, RGB or image-name fields reject the write.
- The master comparison now records both fresh PNG and RGB digests for every page. Selected review transfer also checks the stored source and target PNGs against those fresh renderings. Equal RGB with a different PNG container is rejected.
- A final-discovery snapshot checks both selected image digests, current native queue hashes and every actual native image before completion. It includes the carry/render/record helper versions. No actual observation is generated by snapshotting, rendering, comparing or carrying.

Ten synthetic controls passed, including shifted-page and ambiguous-image cases, stale note rejection, PNG-container differences, ledger locks, and rejection of stale native repair/inspection metadata. These are tooling checks, not visual inspection of any publication page.

## 1. Before replacing the revision578 publications

## 2. After all seven new PDFs are stable and verified with rendering

The ordinary seven-book verification must already have completed with `--render --width 900`. Do not run the following commands against publications still being compiled. Native queues must be prepared after the root has merged the additive finding inventory and the final repair IDs.

Create a unique label from the exact verified seven-PDF set. The following block checks the verification hashes against the actual current PDF files and refuses to reuse an existing carry directory:

```sh
carry_audit_run=$(python - <<'PY'
from pathlib import Path
import hashlib,json
books=['LM_FR_diplomatique','LM_FR_corrige_apparat','LM_FR_texte_de_lecture',
       'LM_EN_corrected_apparatus','LM_EN_reading',
       'LM_FR_master_annotated','LM_EN_master_annotated']
hashes=[]
for book in books:
    verification=json.loads(Path('work/verification',book+'.verification.json').read_text())
    actual=hashlib.sha256(Path('work/build',book+'.pdf').read_bytes()).hexdigest()
    assert actual==verification['sha256'],book
    hashes.append(book+':'+actual)
print('build_'+hashlib.sha256('\n'.join(hashes).encode()).hexdigest()[:16])
PY
)
carry_audit_dir="work/data/carryover_${carry_audit_run}"
mkdir "$carry_audit_dir"

carry_primary_books=(
  LM_FR_diplomatique
  LM_FR_corrige_apparat
  LM_FR_texte_de_lecture
  LM_EN_corrected_apparatus
  LM_EN_reading
)

python work/scripts/prepare_native_closure.py prepare
```

Keep the same shell variables for the subsequent blocks. The stable label prevents a new render set from silently replacing an older inspection index.

## 3. Prepare native queues and attempt exact carry before new native crops

```sh
for carry_book in "${carry_primary_books[@]}"; do
  python work/scripts/prepare_native_closure.py queue \
    --reader "$carry_book" --final
  python work/scripts/carry_native_closure.py carry \
    --snapshot work/data/audit_history/revision578_final_discovery/SNAPSHOT_COMPLETE.json \
    --queue "work/data/final_native_closure_queues/${carry_book}.json" \
    --output "${carry_audit_dir}/${carry_book}_native_carried.json" \
    --report "${carry_audit_dir}/${carry_book}_native_carry_report.json" \
    --final
done
```

The reports list every pending finding and its rejection reason. Reviewers inspect those pending IDs using the current source-qualified queue. Carry registers the exact current copies of historical images in the canonical queue, so run it before reviewers add new crops. Do not regenerate a queue after new observations have begun; doing so discards its registered crops and requires a fresh validation pass.

For a new actual crop, use the existing helper with the actual queued source page and required scale:

```sh
python work/scripts/prepare_native_closure.py crop \
  --queue "work/data/final_native_closure_queues/${carry_book}.json" \
  --finding ACTUAL_FINDING_ID --page ACTUAL_SOURCE_PAGE \
  --scale 8 --clip LEFT TOP RIGHT BOTTOM
```

Replace only the explicit finding/page/rectangle placeholders with the actual queue values. Geometry findings require at least native8x; source heading/tag cases require at least native3x. View the generated images and supply specific observations. Rendering a crop does not clear it.

## 4. Prepare the changed/new selected-page review grids

```sh
for carry_book in "${carry_primary_books[@]}"; do
  python work/scripts/render_pending_review.py \
    "work/verification/${carry_book}" \
    --output "work/verification/${carry_book}/${carry_audit_run}_pending" \
    --width 900 --columns 2 --rows 2
  python work/scripts/review_pages.py queue \
    "work/verification/${carry_book}" \

```

`PENDING_REVIEW_INDEX.json` lists exactly the current pages still lacking attributed review, including their current PDF, PNG and RGB hashes. The second command creates a hash-bearing index of all selected pages, useful when adding a close inspection to an already carried page. Neither command changes review status. An empty pending index is valid.

After actually viewing a disjoint pending grid and saving a page-to-observation mapping, record it with the exact index used for inspection:

```sh
python work/scripts/review_pages.py record \
  "work/verification/${carry_book}" \
  --observations "${carry_audit_dir}/${carry_book}_selected_observations.json" \
  --reviewer ACTUAL_REVIEWER \
  --basis 'Actual current 2x2 full-page review at900px' \
  --inspection-index "work/verification/${carry_book}/${carry_audit_run}_pending/PENDING_REVIEW_INDEX.json"
```

For a later close-view note on an already reviewed page, use `--append` and the hash-bearing `${carry_book}_selected_all.json` index. Do not reuse an earlier revision's note mapping with a new index. The tool validates evidence identity; the observation itself must describe the image actually viewed.

## 5. Combine carried native observations with new actual observations

Each reviewer saves only newly made observations in `${carry_book}_native_actual.json` inside the carry directory. Preserve the queue schema and exact current image hashes. After all pending IDs have actual observations, combine them without changing either source file:

```sh
python - "$carry_audit_dir" <<'PY'
from pathlib import Path
import json,sys
directory=Path(sys.argv[1])
books=['LM_FR_diplomatique','LM_FR_corrige_apparat','LM_FR_texte_de_lecture',
       'LM_EN_corrected_apparatus','LM_EN_reading']
for book in books:
    carried=json.loads((directory/(book+'_native_carried.json')).read_text())['observations']
    report=json.loads((directory/(book+'_native_carry_report.json')).read_text())
    path=directory/(book+'_native_actual.json')
    if report['pending_findings']:
        assert path.is_file(),book
    actual=json.loads(path.read_text()) if path.exists() else []
    if isinstance(actual,dict):
        actual=actual['observations']
    rows=carried+actual
    ids=[row['id'] for row in rows]
    queue=json.loads(Path('work/data/final_native_closure_queues',book+'.json').read_text())
    assert len(ids)==len(set(ids)),book
    assert set(ids)=={row['id'] for row in queue['items']},book
    with (directory/(book+'_native_combined.json')).open('x') as stream:
        json.dump({'observations':rows},stream,ensure_ascii=False,indent=2)
        stream.write('\n')
PY

for carry_book in "${carry_primary_books[@]}"; do
  python work/scripts/prepare_native_closure.py validate \
    --queue "work/data/final_native_closure_queues/${carry_book}.json" \
    --observations "${carry_audit_dir}/${carry_book}_native_combined.json"
done
```

This merge does not create observations or change their statuses. The validator preserves `exact_image_carry`, its original actual observation and all image proofs. Release still requires complete validated coverage and zero unresolved issues. Do not use `--partial` as a final gate.

Run after the primary apparatus selected-page ledgers are complete and both master selected inventories have been rendered. Each comparison reads every corresponding current page and requires both PNG and RGB identity for transfer:

```sh
python work/scripts/compare_pdf_pixels.py \

python work/scripts/compare_pdf_pixels.py \
```

Inspect the different master title pages separately. Use a fresh hash-bearing `review_pages.py queue` output as their inspection index. Any other blocked master page remains pending and needs actual review. The all-page comparison reports support the root's separate master native/pagination/heading transfer gates; they do not themselves invent those confirmations.

Do not rerender the selected images after recording the new reviews. Root's release report refreshes the visual counts directly from the current hash-validated ledgers. If any PDF or source identity changes again, preserve the completed evidence and restart this sequence with a new build label.
